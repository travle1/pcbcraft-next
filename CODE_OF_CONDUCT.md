# Code of Conduct

PCBcraft should be a place where people can ask questions, disagree about designs
and improve the software without being demeaned. Contributors of every background
and experience level are welcome. These expectations apply to project issues, PRs,
reviews and other project spaces, including private interactions about project work.

## Participation

- Discuss behavior, evidence and tradeoffs. Explain criticism of a change without
  attacking the person who made it, and allow room for corrections and learning.
- Respect differences in identity, background, accessibility needs and experience.
- Respect privacy. Obtain consent before sharing another person's personal details,
  private correspondence or sensitive project material.
- Follow reasonable moderation requests, keep contributions relevant and acknowledge
  other people's work and sources accurately.

Harassment, discriminatory abuse, threats, sexual harassment, unwanted repeated
contact, intimidation, doxxing and retaliation for a good-faith report are not
acceptable. Deliberately disruptive spam or fabricated identities/attribution also
undermines participation. Disagreement, an honest mistake or a declined technical
proposal does not by itself constitute misconduct.

## Reporting and response

The project contact is [@travle1](https://github.com/travle1). For a sensitive concern,
use an existing private channel with the maintainer if you already have one.
Otherwise, open a neutral [contact-request issue](https://github.com/travle1/pcbcraft-next/issues/new)
mentioning `@travle1` and asking for a private reporting route. Include **no incident
details, names, private messages or evidence in that public request**. Wait for a
private route before sharing the report. A GitHub profile link is not a private inbox;
this project has not published a separate confidential mailbox.

Once a private route is established, share what happened, relevant links/dates,
any immediate concern and how you prefer to be contacted. Share only what you are
comfortable providing. Reports should be handled discreetly, with information
limited to people needed to respond; absolute confidentiality cannot be promised.

The maintainer may ask for context, request a behavior change, remove content,
restrict a thread, or temporarily/permanently restrict participation depending on
severity and repetition. Serious harm can require immediate action. Where practical,
the affected person receives an explanation and an opportunity to clarify or request
reconsideration. Anyone directly involved in a dispute should avoid deciding their
own case; seek another uninvolved reviewer when available. There is currently no
independent project moderation team.

For abuse on GitHub, especially a concern involving the sole maintainer, GitHub's
own reporting tools are an additional route. For software vulnerabilities, use
[SECURITY.md](SECURITY.md). This policy is original PCBcraft text, not a claim of
adopting a particular version of another project's conduct policy.
