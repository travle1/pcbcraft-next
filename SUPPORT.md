# Help and feedback

Start with the [README](README.md), [editor guide](docs/desktop-guide.md) and
[implementation status](docs/implementation-status.md). The [roadmap](ROADMAP.md)
separates working capabilities from planned ones. PCBcraft is an early standalone
app; help is best-effort, with no commercial support or response-time guarantee.

## Questions, bugs and feature requests

Use [this repository's issues](https://github.com/travle1/pcbcraft-next/issues).
The project maintainer is [@travle1](https://github.com/travle1). There is currently
no PCBcraft Discussions forum, Discord, release-download service or agent queue
configured by these docs. Tangency Labs' channels support their projects; do not
send PCBcraft-specific reports there by default.

Search existing issues/PRs first. Include the exact commit/build, OS, reproduction
steps, expected/actual result and relevant logs. For UI problems, add a screenshot
or short recording with window size and display scale; GPU/backend information can
help rendering reports. Use a minimal original or sanitized project and state its
license if sharing a reusable fixture. Never attach credentials or confidential designs.

For a feature request, describe the design workflow and a concrete acceptance
example. A button or spec entry marked Planned is not a promise that the capability
already works. For a contribution, read [CONTRIBUTING.md](CONTRIBUTING.md).

## Private concerns

Security reports follow [SECURITY.md](SECURITY.md). Conduct concerns follow the
[Code of Conduct](CODE_OF_CONDUCT.md#reporting-and-response). A public issue is not
a private inbox: a contact request should contain only a request for a private route,
not the sensitive report itself.
